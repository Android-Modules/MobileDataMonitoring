# 流量守卫：页面与交互设计

此文记录先行交付的页面设计和交互原型。后续已开发 Android / API 102 模块、安装实测，并适配官方只读查询；当前能力和边界以项目根目录的 `README.md`、`TEST_REPORT.md` 为准。下文“后续开发顺序”是设计阶段记录。HTML 原型中的流量、套餐归属和运营商均为演示，不代表手机实际状态；原型本身不调用 ADB 或移动网络。

## 已确认的需求

- 双卡分别设置国内通用流量和多个定向流量包，独立账期、额度、用量与校准记录。
- 每个定向包支持绑定多个应用、多个识别规则。
- 支持“任一应用或规则命中”和“应用命中且任一规则命中”两种方式。
- 支持停止移动数据、自动切换到有可用额度的卡、固定使用指定卡。用户已确认三种均需要。
- 江苏移动、中国联通的官方流量详情用于定时校准；通过手机上的 HttpCanary 分析真实只读查询请求后再适配。
- 真实测试仅允许卡 2。卡 1 没有流量，禁止启用卡 1 数据和把它作为备用目标。
- 最新授权允许通过 USB 直接控制手机调试；仅卡 2，可用调试流量为 1–5 GB，累计不超过 5 GB，替代此前“小于 1 GB”的要求。首阶段预算 1 GB，最大主动停止线 4.5 GB，预留至少 0.5 GB 缓冲，从小样本开始。
- 先完成页面设计，再开始 Android 开发。本轮不做 Git 提交或分支操作。

### 参考工程 ppx

已读取参考工程配置，确认 `versions.properties` 中 `io.github.libxposed:api` 为 `102.0.0`，应用依赖 `io.github.libxposed:service:102.0.0`，入口模块为 `xposed-modern-api102-entry`。正式开发参考其模块注册、生命周期和配置通信方式，不复制皮皮虾业务 Hook。

libxposed 的公开文档要求模块入口继承 `XposedModule`，在 `onModuleLoaded` 后初始化，并通过 `META-INF/xposed` 注册入口和元数据。参见 [libxposed API 102 文档](https://libxposed.github.io/api/io/github/libxposed/api/package-summary.html)。

Android `NetworkStatsManager` 提供按 UID 查询网络统计和订阅相关参数，但权限和订阅标识可用性有限；不能仅凭模块激活就宣称支持完整双卡细分。参见 [Android 官方文档](https://developer.android.com/reference/android/app/usage/NetworkStatsManager)。

## 统计和校准约定

1. **总量来源唯一。** 蜂窝接收与发送字节作为总账；应用、连接和规则是同一笔用量的分类证据，不再叠加到总账。Wi-Fi 排除。
2. **按卡身份记账。** 槽位和当前 subscriptionId 只用于定位；重启、换卡、开关卡及副卡变更后重新建立映射。无法确定归属的样本进入未归属记录，不能默记到卡 2。
3. **估算与官方分开。** 应用绑定不能证明应用所有流量均扣定向；第三方广告、SDK、网页或下载器可能不同。UID、域名等证据可以不完整，使用“待验证／不可识别”状态。
4. **去重及优先级。** 同一笔用量只归属一个包。规则和应用同时命中时不双算；多个包命中按优先级处理。套餐真实扣费优先级仍以官方规则和结果校准。
5. **保护采用保守值。** 未验证、过期、耗尽或额度未知的定向包，不降低通用流量保护预算。账单与本地状态冲突时显示差额及时间，避免错误地扩大可用额度。
6. **校准使用有时间的快照。** 保存卡身份、周期、官方包 ID、额度与单位、官方统计截至时间、拉取时间、原始本地计数、调整值。当前估算为官方截至时间对应基准加之后的本地增量；不能把拉取时间冒充官方统计时间。
7. **未知延迟不强行对齐。** 无统计截至时间、时间错位、账期不匹配、单位不明或包 ID 映射不明时，不自动覆盖保护基准，标记待处理。相同快照重复应用不得重复累计差额；保留历史可追溯。
8. **未知不是无限量。** 截图中移动云盘仅显示“已用 0”，不能推断套餐不限量。套餐总量未知时独立标记，并要求核实。
9. **共享套餐不能随意相加。** 30 GB 云电脑包与 70 GB 多 SID 套餐在原型中单列；截图没有给出完整适用范围，不能假定同一应用可直接使用 100 GB。共享包还须考虑其他成员的官方用量。
10. **运营商账号与设备 SIM 独立。** 联通 App 可以登录不在当前设备 SIM 中的账号；经卡 2 查询的账号不自动归属卡 2。先确认账号与卡身份的映射，再应用校准。

## 联通 App 实机观察

已查看手机中中国联通 App 13.2 的余量页，仅执行查询页面导航，没有进入套餐变更、充值、订购或领取操作。

- 页面按“通用流量”和“专属流量”汇总，并显示查询时间；该查询时间不直接证明运营商计费统计截至时间。
- 当前登录账号页面提供 3 个号码的“成员使用情况”，流量包标注“共享”。这属于该账号的实际页面结构，不能推广为所有联通套餐都共享。
- 通用列表存在多个名称相似但批次不同的 10 GB 流量奖励包；不能只按显示名称合并，正式适配需要稳定的官方包 ID。
- 专属列表分别存在 10 GB、30 GB 王卡专属免流包；应逐包保留总额、已用、剩余和共享属性，不把总览与子包重复相加。
- 后续数据模型包含：运营商账号、官方包 ID、官方原类别、共享池标识、成员关系、共享总用量、本卡用量、计量单位与统计时间。界面统一显示通用／定向，保留联通的“专属”原标签。
- 设备当前报告两张 SIM 的运营商品牌均为中国移动，因此联通登录账号尚不自动映射到任一卡槽。待实际卡身份与账号关系确认后才能应用官方校准。

设备截图与临时预算基线保存在被 Git 忽略的 `.private/`，不写入原型，也不在文档记录完整号码或登录凭据。手机当前为 Android 16 / HyperOS 3，Root 可用；已核对物理卡槽 2 对应当前订阅 2，默认和活动数据订阅均为 2。订阅号不是跨换卡和重启的永久身份。

## 保护状态和测试约束

正式模块的策略决策应独立于页面运行，重启后保留预算、锁定状态和最后执行结果。

- 预警 → 达到安全线 → 停止当前数据或校验备用卡 → 执行 → 验证回执 → 记录与通知。
- 自动切卡需要目标卡已允许、额度可信且高于预留、信号可用，并满足冷却期；没有合格目标时停数据。
- 固定卡策略同时阻止系统自动切卡。用户主动修改策略需要清晰反馈；设备重启和系统更新后重新探测控制能力。
- 不能只记录“请求切卡”，必须核验真实默认数据卡和数据状态。失败时不无限切换，不显示执行成功。
- 功能不可用时明确显示“不可用／保护未执行”，保留恢复方式与失败原因。UI 关闭不代表保护服务停止。
- 测试模式覆盖普通自动切卡设置：永远只允许卡 2。检测到另一张卡、热点／后台干扰导致预算不可确定、计数不可读或服务失联时，停止测试。
- 首阶段默认累计停止线为 1000 MB，可配置的主动停止线最多 4500 MB；总授权上限为保守的 5,000,000,000 字节。实际限制需要依据采样间隔、峰值速率和在途字节进一步收紧；未验证控制回路前不进行大流量测速。
- 累计预算覆盖全部测试任务及失败重试，包含测试期间后台蜂窝流量，不通过暂停、换资源、重启清零。实际下载只取少量可控字节，先验证限额中断。
- 官方扣费延迟可能使短时间对比没有结论。结果可以是“未确定”，不可为了等待可见扣费反复下载。

## 后续开发顺序

1. 用已审阅页面建立 Kotlin / Compose 应用与 libxposed API 102 入口，完成本机配置存储与真实能力探测。
2. 实现按卡蜂窝总量、UID 分类、周期和有时间的校准账本；先验证重启、换卡和统计去重。
3. 实现停数据、自动切卡、固定卡的状态机和执行回执；通过模拟与最小实机请求验证。
4. 从 HttpCanary 的真实只读查询中适配江苏移动和联通，处理鉴权失效、签名与限频。不能承诺仅靠 URL 就能长期自动查询。
5. 实现可见字段范围内的规则识别，并用卡 2 的小样本对照官方通用／定向扣费。HTTP、HTTPS、QUIC、VPN 和原生网络库的覆盖范围逐项标记，未覆盖不伪报精确。

## 设计原则与范围

- KISS：四个主导航，套餐编辑集中完成多应用和多规则配置。
- DRY：所有卡复用同一套配置和展示结构，统计总账只有一个来源。
- 单一职责：统计、规则分类、校准、策略与系统控制分别设计，UI 不承担保护决策。
- YAGNI：当前只保留双卡、流量包、查询校准和保护需求，不添加账户云同步、远程操作或订阅商城。

当前原型的开始／暂停／停止仅改变本地演示状态；不会调用任何下载地址、官方接口、ADB 或移动网络。设计设置可由会话保存；尚未实现正式持久化和 Android 系统能力。

## 原型核验

已在浏览器检查 320 px 和 736 px、浅色和深色下的 10 个主要视图，未发现横向溢出或脚本异常。已核验多应用／多规则保存、组合条件校验、按卡配置隔离、校准差额只应用一次、离线测试预算跨页面保留及达到停止线后停止。

联通共享包另行核验：缺少共享池标识时阻止保存；填写账号备注、成员数和共享池后正确展示；重复共享池标识阻止再次创建。以上均为页面行为核验，不代表实机统计、运营商查询或保护执行已通过验证。
